# Арена: Рикошет

## Сборка и текущий выпуск

### Компактный интерфейс

Главное меню начинается с трёх действий: «Волна · играть», «Дуэль с другом» и «Настройки и профиль». Описание волны, сложность, опыт, результаты, магазин, управление и состояние сохранения находятся в последнем разделе. После результата и выхода из волны раздел остаётся свёрнутым; результаты можно раскрыть вручную. При конфликте сохранений или ошибке синхронизации он открывается, чтобы не скрывать требуемое действие.

Во время игры остаются арена, верхняя строка счёта и четыре компактные кнопки: ✦ удар, Ⅱ/▶ пауза/продолжение, ↪ выход, ? помощь. Под квадратным полем в режиме одного пальца расположена площадка управления, сразу за ней — магнит с полосой энергии. Поле занимает доступную ширину или высоту без искажения геометрии. Помощь открывается поверх игры и ставит матч на паузу; после закрытия нужно нажать продолжение. На компьютере правая кнопка мыши над полем включает магнит, левая сохраняет точный удар. Контекстное меню подавляется только на игровом поле во время матча.

### Прогрессия, сложность и магнит

В меню показаны текущий уровень, полоса опыта и ближайшее ещё не купленное оформление. Это цель для покупки за осколки, не автоматическая награда за уровень. Экран результата расположен перед меню: номер волны, сложность, длительность, пропущенные мячи, точные удары и голы после последнего касания твоим отражателем. Гол, перед которым шар отбил бот, тебе не засчитывается. Опыт и осколки начисляются только за завершённую волну; выход через меню награды не даёт.

Сложности «Легко», «Обычно», «Сложно» меняют скорость, точность и реакцию ботов. Награды и физика шара одинаковы. Сложность выбирается до старта и запоминается на устройстве; это настройка, она не переносится через VK вместе с прогрессом. В дуэли сложность не применяется.

Магнит работает только в одиночных волнах. Начальная энергия — 50, точный удар добавляет 25, максимум — 100. Кнопка тратит 100 энергии и включает захват на 4 секунды. Первый шар, попавший на твой отражатель, удерживается 1 секунду, следует за отражателем, затем автоматически летит вверх. Если шар не пойман, энергия всё равно потрачена. Удерживаемый шар не сталкивается с остальными; пауза замораживает время действия. Между волнами энергия сбрасывается. Перезарядка точного удара остаётся 0,8 секунды. Всё доступно одним пальцем: включи магнит кнопкой и продолжай вести отражатель по площадке.

Проверки: расчёт уровней, одинаковые награды на разных сложностях, захват/выпуск/пауза/окончание действия магнита, сохранение настройки сложности, кнопка магнита и статистика результата в браузере. Ручная проверка на телефонах внутри VK отложена по решению пользователя.

Обновление 7 ноября 2026: добавлена раскрывающаяся справка «Как играть», которая открыта при первом запуске и запоминает кнопку «Понятно». В настройках можно отдельно включить звук и вибрацию; по умолчанию они выключены. Звуки синтезируются на устройстве без загрузки файлов, вибрация работает только там, где её разрешает браузер. Столкновения сопровождаются кольцами, голы — цветной рамкой, точный удар — подсветкой отражателя и сообщением.

Цикл одиночной игры теперь содержит шесть испытаний: «Классика», «Перекрёстный огонь», «Мультибол», «Узкий проход», «Шесть рикошетов», «Диагональ». Скорость подачи растёт раз в шесть волн; номер уже открытой волны сохраняется. Симуляция хоста дуэли обновляется примерно 60 раз в секунду с фиксированным физическим шагом, сетевые снимки — примерно 20 раз в секунду. Интерполяция гостя и испытания двух физических устройств остаются дальнейшей работой, плавность на любых сетях не гарантируется.

Граница готовности: это проверенная браузерными тестами версия для игровых испытаний. Перед модерацией ещё нужны ручные проверки Android/iOS внутри VK, сохранений на двух устройствах и реального прямого соединения. Публичные комнаты, рейтинг и монетизация не подключены. Альтернативы дуэли сохранены в «Варианты развития.txt» и «Решения по дуэли.txt».

Исходники интерфейса находятся в public, общая физика и награды — в physics.js.
Команда npm run build создаёт три автономных файла index.html, web.html и mobile.html.
Готовый комплект для публикации находится в папке «Релиз для GitHub Pages».
Все три файла содержат VK Bridge, физику, интерфейс и локальный сеанс. Дополнительная загрузка скриптов при открытии не требуется.

    npm ci
    npm run build
    npm test
    npm run test:browser

Для браузерной проверки используется установленный Microsoft Edge. На другой машине можно указать путь к Chromium через BROWSER_PATH.
Проверка создаёт временный браузерный профиль, тестирует размеры экрана, жесты, паузу, сохранение, серверный клиент и сигнал инициализации VK.

Текущий выпуск — одиночные волны, оформление отражателя за заработанные осколки и прямая дружеская дуэль с ручным обменом кодами. Платные услуги, платежи, сторонние сетевые сервисы и реклама не подключены. В автономные HTML-файлы включён WebRTC-клиент без STUN/TURN; серверный WebSocket-клиент не включается. Серверные исходники ниже — отложенный прототип, не опубликованный игровой сервер.

Вне VK прогресс хранится на устройстве. При запуске с параметрами аккаунта VK игра использует VKWebAppStorageGet/Set: перед волной читает сохранение, после результата и выбора оформления записывает. Подтверждённая запись обозначается сообщением «Прогресс сохранён в VK». При сбое остаётся локальная копия и кнопка повтора. Локальные копии разделены по приложению и аккаунту; старое анонимное сохранение переносится в пустое хранилище VK только кнопкой игрока. Доступ к друзьям, телефону и почте не запрашивается.

Если обнаружена другая версия сохранения, игра предлагает выбрать облачную или локальную. Перед заменой создаётся резервная копия на устройстве. VK Storage не предоставляет в используемом интерфейсе атомарной проверки версии: одновременная запись с двух устройств всё ещё может привести к конфликту. Играйте с одного устройства за раз; перед переходом дождитесь подтверждения сохранения. Клиентское хранилище предназначено для одиночной игры, не защищает рейтинг или платную валюту от подмены.

Покупки оформления требуют подтверждения, повторная покупка не списывает осколки. Все четыре оформления отличаются только цветом отражателя. Автоматические проверки VK используют имитацию Bridge; реальная доступность хранилища зависит от типа приложения и клиента VK и требует проверки опубликованной версии.
Экспортные папки формируются из исходников. Правки в них следует вносить через исходники и повторную сборку.

## Дуэль с другом без посредников

1. Оба игрока открывают игру и выбирают «Дуэль с другом · обмен кодами».
2. Хозяин нажимает «Я хозяин · создать приглашение», копирует весь код RK1. и отправляет другу через удобный мессенджер.
3. Друг вставляет приглашение в поле «Код от друга», нажимает «Я гость · создать ответ» и возвращает свой код хозяину.
4. Хозяин вставляет ответ в то же поле, нажимает «Принять ответ друга». После подключения нажимает «Начать матч».

Нужно держать исходные страницы открытыми: обновление страницы аннулирует приглашение. Коды действуют 30 минут и подходят только к конкретной паре приглашение/ответ. Данные передаются через RTCDataChannel, физика считается только хозяином. Первый до 7 голов или лидер через 120 секунд побеждает; ничья продолжается до следующего гола. При сворачивании матча запрашивается общая пауза. Короткий разрыв соединения может восстановиться; при закрытии страницы или длительном отсутствии связи нужен новый обмен кодами. Переноса роли хозяина нет.

Проверка соединения использует `iceServers: []`: нет внешнего сервиса сигнализации, STUN или TURN, нет платы за сетевой сервис. Это существенно ограничивает доступность через интернет. Начните с двух устройств в одной обычной Wi-Fi-сети; гостевая изоляция Wi-Fi, NAT оператора, ограничения браузера или VK WebView могут помешать даже там. После принятия ответа ожидание соединения ограничено 25 секундами, затем выводится ошибка. Нельзя обещать работу между произвольными мобильными сетями.

Коды содержат параметры сетевого соединения, передавайте их только другу. Прямая связь может раскрывать IP сопернику. Дружеские матчи доверяют хозяину и не начисляют XP, осколки или рейтинг. Нет запроса друзей или отправки сообщений от имени пользователя. Сохранения одиночной игры не меняются.

`npm run test:peer` проверяет настоящий WebRTC между двумя страницами Edge: обмен кодами, управление обоих игроков, паузу, итог, разрыв, повторный вход и неизменность прогресса. Это локальная проверка на одном компьютере; соединение между реальными телефонами внутри VK и через разных операторов не проверено автоматически.

## Управление одиночной игрой

В мобильном входе по умолчанию включено управление одним пальцем. Площадка под полем позволяет двигать отражатель, сохраняя обзор арены. Отпускание пальца запускает импульс, если он готов. Чувствительность настраивается в раскрывающемся разделе управления.

В режиме «По позиции» отражатель следует за мышью или касанием. Щелчок включает импульс. Также работают стрелки и пробел.

Кнопка «Пауза», сворачивание окна и событие скрытия приложения VK приостанавливают одиночную волну. Возобновление происходит по кнопке «Продолжить». Выход из волны требует подтверждения. В сетевой дуэли действует общий ход матча и правила переподключения.

Оранжевые ворота внизу принадлежат игроку. Бирюзовые ворота — цели. Появление новых шаров, голы и точные удары сопровождаются сообщениями, а кнопка удара показывает готовность и перезарядку.

Одноэкранная HTML5-аркада для VK Mini Apps. Клиент рисует объёмный стол средствами Canvas 2D. Node.js ведёт физику с фиксированным шагом 1/60 секунды, принимает положение отражателя и команду удара по WebSocket и сохраняет результаты в SQLite. Все участники дуэли имеют одинаковые характеристики.

## Локальная игра

Требуется Node.js 24. Из каталога проекта выполните:

    npm ci
    npm start

Откройте http://127.0.0.1:3000. Для проверки дуэли откройте второе независимое окно инкогнито, создайте комнату в первом и введите её код во втором. В демонстрационном режиме профиль привязан к гостевому идентификатору вкладки. Сервер слушает только loopback.

В волнах игрок защищает нижнюю сторону, ещё три стороны занимают боты. При пропущенном голе сторона теряет прочность. Испытания повторяются циклами: классическое поле (новые шары на 35-й и 70-й секундах), бамперы ромбом (30 и 60 секунд), ранний мультибол (20 и 40 секунд). Меню показывает описание и расположение бамперов следующего испытания. Победа открывает следующую волну; скорость, реакция и точность ботов растут до заданных пределов. Начальная скорость шара увеличивается каждый цикл до 480 единиц/с, максимальная после ударов — 740. Это начальный баланс для игровых проверок. Старый локальный прогресс сохраняется. При ничьей по оставшейся прочности на отметке 150 секунд живой игрок проходит волну. Дуэль не зависит от уровня и волн: семь голов или лидер через 120 секунд, при равенстве — следующий гол. На переподключение даётся 30 секунд. При досрочном выходе из дуэли первые 15 секунд награды отключены.

Двигайте мышью, перетаскивайте отражатель пальцем или нажимайте стрелки. Направление отскока зависит от точки контакта. Для ускоренного удара нажмите пробел или кнопку перед касанием. Окно точности 170 мс, перезарядка 800 мс.

## Подключение к VK

Разместите один постоянно работающий процесс Node за HTTPS reverse proxy на том же домене, проксируйте WebSocket Upgrade для /play и укажите HTTPS-адрес в настройках игры VK. Для нескольких процессов потребуется общее хранилище комнат и маршрутизация сессий. Перезапуск процесса завершает активные матчи, записанные результаты сохраняются.

На сервере задайте VK_APP_ID, VK_SECRET и PUBLIC_ORIGIN (например https://arena.example без завершающего слеша). Установите постоянный случайный PROFILE_KEY до первого запуска, чтобы ротация секрета VK сохраняла привязки. DB_PATH должен указывать на файл на постоянном томе вне публичного каталога. PORT по умолчанию 3000. В рабочей среде задайте NODE_ENV=production для обязательной проверки конфигурации.

Сервер проверяет HMAC-подпись, ID приложения и возраст запуска, сохраняет псевдоним аккаунта, опыт, осколки, волну и рейтинг. Email, телефон и список друзей игре не требуются. Настройте HTTPS/WSS, права доступа к базе и резервным копиям, отключите запись строки запроса с launch-параметрами в логи прокси. В течение 10 минут подписанная ссылка позволяет повторный вход, поэтому её нельзя передавать сопернику. Для приглашения передавайте только код комнаты. После истечения этого окна для нового подключения нужно заново открыть игру в VK.

## Боковой баннер

В меню клиент запрашивает вертикальный Sticky banner с выравниванием вправо. 160 CSS-пикселей свободного места — внутренний порог попытки, размер креатива сообщает Bridge. Клиент сверяет фактические размеры с местом справа и скрывает неподходящий формат. При узком экране запрос пропускается. Перед созданием комнаты и стартом волны баннер скрывается. Нужны подключённая монетизация и проверка размещения в реальном приложении.

В приложении № 1 к [оферте VK](https://apiok.ru/apps/launch/documents/contract/adv/offer_new/) указано 17 ₽ за 1000 показов Sticky banner и 25 ₽ для Native Sticky banner, без НДС. Доход считайте по зачтённым показам и формату из отчёта подключённого приложения. [Параметры официального Bridge](https://github.com/VKCOM/vk-bridge/blob/master/packages/core/src/types/data.ts).

## Проверка

    npm test

Тесты используют отдельную БД в памяти и тестовую подпись. Проверяются удар, гол, овертайм, мультибол, доступ к публичным файлам, отказ при неверной подписи, дуэль двух клиентов, переподключение и получение награды с нового устройства. Перед публикацией нужны испытания на iOS, Android и в веб-клиенте VK, при задержках и на реальной рекламе. Магнит, магазин, сезоны и турниры относятся к следующим версиям.

Визуальное различие ворот и отражателей: ворота — тёмный проём с тонкой сеткой и боковыми стойками (свои красные, цели бирюзовые). Отражатель — объёмная светлая платформа с контуром и тремя насечками, свои цвета зависят от оформления, у соперников серебристый металл. Изменён только рисунок, размеры столкновений и физика прежние. Три главных пункта меню используют единый шрифт и отступ 16 пикселей слева.

Декоративные эффекты: короткий след шара сбрасывается при подаче, паузе и новой партии; ворота выбывшего бота закрываются металлической заслонкой и помечаются «ЗАКРЫТО». При начале и завершении волны кратко появляется уведомление, не блокирующее управление. Настройка «Уменьшить эффекты» убирает след, кольца столкновений и вспышку рамки, делает закрытие ворот мгновенным; подсказки готовности способностей остаются. По умолчанию учитывается системное prefers-reduced-motion, явный выбор сохраняется на устройстве.
Реклама и реальные покупки не подключены. Проверенные сведения и отдельный план подключения находятся в файле «Монетизация — статус и следующие шаги.txt».

Актуальное решение по рекламе от 7 ноября 2026: только компактный нижний баннер во время игры в свободной области под магнитом. Без рекламы в меню, rewarded и interstitial. Рамка вокруг места — пожелание, пока не подтверждённое правилами VK. При недостатке свободного места баннер не показывать и поле не уменьшать. Это заменяет прежние предложения монетизации; подробности в файле «Монетизация — статус и следующие шаги.txt». Реальные показы пока выключены.

Тестирование рекламы: «Настройки и профиль» → «Управление, звук и вибрация» → «Проверка баннера». По умолчанию выключено; «Макет» показывает подписанный тестовый блок, «Реклама VK» запрашивает настоящий баннер только внутри VK. На широком десктопе (web.html, от 900px) поле смещено вправо, реклама слева; на узком экране снизу. Только в активном матче, без рекламы в меню и паузе. Режим сохраняется на устройстве. Фактические размеры VK проверяются после показа; первый показ нуждается в проверке на реальном устройстве. Команда npm test включает тесты banner-ads.test.js. Актуальный статус подключения и ограничения — в начале файла «Монетизация — статус и следующие шаги.txt».

Исправление автоматического показа: внутри VK режим по умолчанию теперь «Реклама VK», вне VK — «Выключен». Старое автоматически сохранённое off больше не блокирует старт; новый ключ rikoshet-banner-choice-v2 хранит только явный выбор пользователя. Рекламный запрос ожидает подтверждения VKWebAppInit. Последние шесть диагностических сообщений сохраняются в настройках, включая код и текст ошибки SDK. Это не подтверждение наличия тестового инвентаря: результат фактического показа нужно проверить в клиенте VK.
